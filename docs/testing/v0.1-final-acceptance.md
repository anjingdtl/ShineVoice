## 一、ZipVoice 50 次稳定性与内存趋势（instrumented test07）

方法：初始化 → 3 次预热真实生成 → GC+静置稳定 → 记录基线 → 连续 50 次真实生成，
每 5/10/20/30/40/50 次记录 PSS / Java Heap / Native Heap（logcat `E2E_MEM_CHECKPOINT`）。

| 检查点 | PSS (KB) | Java Heap (KB) | Native Heap (KB) |
|--------|----------|----------------|------------------|
| run 0（预热后基线） | 605,172 | 2,564 | 560,378 |
| run 5 | 601,951 | 2,516 | 560,390 |
| run 10 | 612,850 | 2,516 | 560,770 |
| run 20 | 635,252 | 2,516 | 561,530 |
| run 30 | 645,464 | 2,516 | 561,986 |
| run 40 | 645,361 | 2,532 | 562,003 |
| run 50 | 645,793 | 2,532 | 562,023 |

结果统计：**50/50 成功**；平均耗时 1,145 ms、最大 1,250 ms；平均 RTF 0.194、
最大 0.214；耗时按 10 次分块均值 1048 → 1132 → 1181 → 1180 → 1186 ms（先升后稳）。
Crash / ANR / Native Error：0。

**结论：无线性内存泄漏。** PSS 与 Native Heap 增长集中在 run 0→30（推理池/张量
Lazy Allocation），run 30 后平台化——最后 20 次生成 PSS 仅 +329 KB（≈+16 KB/次，
属分配器噪声），Native Heap 仅 +37 KB。Java Heap 全程恒定 ≈2.5 MB。

## 二、三 Provider 严格切换（instrumented test04，重写）

方法：本地生成 → 系统语音 → 云端高清，循环 7 轮 = **21 次真实生成**；每次断言
`result.providerId == 请求 providerId`、voiceId 回显一致、输出为合法 WAV；云端
限流退避 6 s 重试一次，其余任何失败按 FATAL（不再降级 non-fatal）。

- 结果：**21/21 成功，0 失败，0 串线**。
- 本地生成：回显 `zipvoice_local` / `default_reference`，876~1,978 ms。
- 系统语音：回显 `android_system_tts` / `cmn-cn-x-ccc-local`，97~252 ms。
- 云端高清：回显 `minimax` / 克隆音色 `svf7e3***ccbc`（本轮现场克隆，id 长 18），
  978~4,122 ms；测试前 `validateConfig` 连接预检通过。
- 全程无 Player 冲突、无重复错误初始化、无 Crash/ANR；21 条记录全部正确写入历史。
